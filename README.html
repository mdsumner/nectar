Need a bigger computer?

The ARDC Nectar Research Cloud lets Australian researchers create their own virtual machines (VMs): computers in a data centre that you start, log in to, install what you like on, and delete when you’re done. It’s free for researchers, and it sits between your laptop and a supercomputer.

This page is a short way in, and a list of places to go next.

Status: early draft. The old notes this grew out of are in legacy/.

Is this for me?

Probably, if:

  • your laptop is too slow, too small, or you need something running overnight or for weeks;
  • you want a machine you control: your own software, your own users, always on;
  • you want to serve something on the web (RStudio Server, Jupyter, marimo, Shiny, a website, a data service), or to work on a remote machine from Positron or VS Code over SSH;
  • you use HPC but want something interactive alongside it.

If you have a university email address (.edu.au), try logging in now: go to the Nectar dashboard and choose Login via AAF. If it works, you already have a small personal allocation (a Project Trial) and can launch a VM today. Not sure you’re eligible? Use the eligibility checker.

The trial is small (up to 4 cores, for 6 months). When you need more, you apply for your own allocation. How to think about that, and how big a machine you need:

  • Your allocation: the trial, applying, renewing, what happens at expiry
  • Sizing: how big a machine is, and turning that into Service Units
  • The words: project, allocation, flavour, image, instance, volume

What do I actually do?

Six steps. Each one has a “more” link if you get stuck; otherwise just do it. Nothing here is precious. If something goes wrong, delete the VM and start again.

  1. Log in to the dashboard with AAF. More
  2. Check your allocation. Your Project Trial (pt-NNNN) is selected at the top left. More
  3. Create a keypair, and save the private key. This is how you’ll log in; there are no passwords. More
  4. Allow SSH in. A security group is a firewall rule. Without one that allows SSH you can see your VM but not reach it. More
  5. Launch an instance. Pick an image (Ubuntu), a flavour (size), your security group, and your key. A VM launched without a key can’t be logged in to; delete it and launch another. More
  6. Connect with SSH: ssh ubuntu@<ip>. More

That’s it: you have a computer.

Next: put something on the web. RStudio Server behind HTTPS with a proper name, or the dashboard’s one-click “Quick Deploy” for RStudio.

Once you’re using it:

  • Storage: volumes, object storage, network mounts
  • Software: R and geospatial stacks, containers, Python
  • Looking after it: users, updates, snapshots, shelving, handing it back

How Nectar fits

Compared with AWS EC2

Same idea, different deal. Nectar runs OpenStack, and most EC2 words have a direct match: instance type → flavour, AMI → image, EBS → volume, S3 → object storage (Nectar’s has an S3-compatible API), and security groups and keypairs are the same. The differences are that Nectar is free to eligible researchers, paid for with an allocation of Service Units instead of a credit card, and it has no managed databases, queues or serverless: you get VMs, storage and DNS. More

Compared with HPC

HPC (supercomputers and university clusters) is for big batch jobs: you submit work to a queue, it runs across many cores, and the centre looks after the software. A Nectar VM is yours. It’s interactive, always on, you have root, and you maintain it (ARDC: cloud vs HPC). Many people use both. If you have an HPC project, interactive work is possible there too: NCI’s ARE runs RStudio and Jupyter in the browser, and both NCI and Pawsey document running them inside a job. More

  • NCI: Gadi, the national supercomputer
  • Pawsey: Setonix, and since December 2025 also a Nectar node
  • Monash: a Nectar node and university HPC
  • QCIF: runs the Queensland Nectar node (QRIScloud) for UQ, QUT and other Queensland members, and brokers HPC access
  • Your own university’s research computing team, who often run a cluster and can help with a Nectar allocation

The node network

Nectar is run by partner organisations (“nodes”), each with its own data centre. Your institution’s node can approve local allocations; national allocations are approved centrally and can run anywhere. The nodes are Intersect (NSW), Queensland, Adelaide, Tasmania, Melbourne Research Cloud, Monash, Swinburne, Pawsey, National (ARDC-AARNet), and Auckland (NZ) (current list and members).
